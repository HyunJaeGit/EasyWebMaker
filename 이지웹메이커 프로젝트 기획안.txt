이지웹메이커 프로젝트 기획안
작성일 2026년 10월 11일  |  버전 1.1  |  첫 MVP 요구사항 확정
1 프로젝트 개요
블록을 드래그하여 반응형 단일 페이지 사이트를 제작하고, 재편집 가능한 프로젝트 파일과 배포 가능한 HTML·CSS·JS 파일을 다운로드하는 웹 서비스다. 초기에는 로그인 없이 핵심 기능을 사용할 수 있게 한다. 회원 화면은 데모로 제공하고, 실제 인증·온라인 저장·프리미엄 구독은 후속 단계에서 도입한다.
목표 사용자는 코딩 경험이 적은 취업 준비생, 개인 창작자, 소규모 사업자다. 초기 샘플은 베이직한 한국 학교 홈페이지와 공공기관 홈페이지 스타일로 제공한다. 실제 기관의 로고·콘텐츠를 복제하지 않고 가상 기관의 예시 콘텐츠를 사용한다. 개발 목표는 편집 결과와 출력 결과의 일치, 저장과 복원의 안정성, 정적 호스팅 배포의 재현성을 확보하는 것이다.
2 제품 범위와 원칙
MVP 포함: 단일 페이지 제작, 기본 블록 조립, 글·이미지·링크 수정, 제한된 스타일 편집, PC·모바일 미리보기, 실행 취소·다시 실행, 프로젝트 저장·불러오기, 사이트 ZIP 다운로드, GitHub Pages 배포용 파일과 안내, 로그인·회원가입 UI 화면. 실제 인증과 구독 기능은 제외한다.
후속 범위: 실제 회원가입·로그인, 계정별 온라인 저장, 버전 기록, 유료 구독과 결제, 고급 블록, React 프로젝트 출력, GitHub 계정 연동 자동 배포. 초기에는 다중 페이지, 임의 JavaScript 입력, 서버 기능 생성, 외부에서 임의로 수정한 코드의 완전한 역수입은 보장하지 않는다. 이지웹메이커가 저장한 패키지의 불러오기와 재편집은 MVP에 포함한다.
시맨틱 HTML은 콘텐츠 역할에 맞는 header·nav·main·section·footer 등의 태그를 출력하는 원칙이다. Semantic UI 라이브러리 채택을 의미하지 않는다. 레이아웃은 구역과 컨테이너 안에서 조립하며 자유 좌표 배치를 기본으로 삼지 않는다.
3 사용자 경험과 화면
홈 화면
서비스 설명, 제작 과정, 샘플 사이트 미리보기를 제공한다. 히어로에는 ‘나만의 사이트 만들기’를 표시한다. 사용자는 빈 프로젝트 또는 ‘이 샘플로 시작하기’를 선택한다. 로그인 요구 없이 제작 페이지로 이동한다.
제작 페이지
왼쪽은 블록 목록, 중앙은 편집 캔버스, 오른쪽은 선택한 블록의 속성 패널로 구성한다. 블록을 드래그하여 삽입·이동하고 클릭하여 내용을 수정한다. 상단에는 프로젝트 이름, 실행 취소·다시 실행, 화면 크기 전환, 미리보기, ‘저장·내보내기’를 배치한다.
잘못된 위치에는 드롭을 허용하지 않고 삽입 위치를 표시한다. 블록 복제·삭제와 버튼을 통한 순서 이동도 제공한다. 미리보기에서는 편집 테두리와 도구를 숨긴다. 페이지 전환으로 편집 내용을 초기화하지 않으며, 작업 손실 가능성이 있는 이탈에는 안내한다. 편집기는 PC뿐 아니라 태블릿·모바일 웹에서도 사용 가능해야 한다. 작은 화면에서는 블록 목록과 속성 패널을 접이식 패널로 제공하고, 터치 조작과 클릭 삽입·순서 이동을 지원한다.
저장 페이지
프로젝트 이름과 결과 미리보기를 보여주고, HTML·CSS·JS와 이미지 및 재편집 데이터를 하나의 ZIP으로 저장한다. 사용자는 이 ZIP을 다시 불러와 편집할 수 있다. 사이트 다운로드에서는 일반 정적 호스팅 또는 GitHub Pages를 선택한다. GitHub Pages에서는 브랜치 기반과 Actions 기반을 구분한다. 파일 목록과 배포 안내를 확인한 뒤 ZIP을 받으며, ‘편집으로 돌아가기’에서도 작업을 유지한다.
4 기본 블록과 편집 기능
초기 블록은 헤더·메뉴, 히어로, 텍스트, 이미지, 카드 묶음, 버튼·링크, 구역·컨테이너, 푸터로 구성한다. 카드 묶음은 항목 추가·삭제와 열 배치를 지원한다. 이미지는 업로드와 대체 텍스트 입력을 제공한다. 메뉴와 링크는 외부 URL 또는 같은 페이지의 구역으로 연결한다.
공통 스타일은 글자·배경 색상, 글자 크기, 정렬, 내부·외부 여백, 테두리, 모서리, 콘텐츠 너비와 간격을 지원한다. 블록별 허용 속성을 제한하여 구조를 보호한다. 초기에는 PC 기준 스타일과 정의된 모바일 규칙을 적용하고, 화면 크기별 임의 스타일 편집은 후속 검토한다.
반응형 기준은 카드의 세로 배치, 이미지의 컨테이너 초과 방지, 메뉴의 모바일 전환, 가로 스크롤 방지다. 결과 사이트는 키보드로 접근 가능한 링크·버튼과 의미 있는 제목 구조를 갖춘다.
5 저장과 내보내기
프로젝트 파일
저장 형식은 실행용 index.html·styles.css·script.js, assets 폴더와 재편집용 project.json을 하나로 묶은 ZIP을 기준으로 한다. 별도의 전용 프로젝트 ZIP을 요구하지 않는다. project.json은 실행 파일과 별도로 블록 구조와 편집 상태를 정확히 복원하기 위한 동반 데이터다. 데이터에는 프로젝트 이름, 블록 식별자·종류·계층·순서, 내용, 스타일, 자산 참조를 담는다. 불러오기 전에 형식·버전·참조를 검증하고 잘못된 파일은 현재 작업을 덮어쓰지 않는다. 생성된 HTML은 원본 편집 데이터로 사용하지 않는다.
사이트 파일
기본 출력은 index.html, styles.css, script.js와 assets 폴더다. script.js는 항상 포함하되 동작이 없는 경우 실행 로직을 추가하지 않는다. 출력에는 편집 엔진의 인터페이스와 편집용 속성을 포함하지 않는다. 업로드 이미지를 함께 포함하고 사이트 자산은 하위 경로 배포에 대응하도록 처리한다.
GitHub Pages 배포 패키지
GitHub Pages는 배포 대상이며 Actions는 배포 실행 방식이다. 브랜치 기반 패키지는 사이트 파일과 저장소 설정 안내를 제공한다. Actions 기반 패키지는 사이트 파일, .github/workflows/deploy.yml과 설정 안내를 제공한다. 워크플로는 선택한 배포 구조에 맞춰 생성하고 로컬에서 설정과 패키지를 검토한다. 실제 저장소 배포 검증은 사용자 연결 이후 진행하며 현재 작업에서는 저장소를 생성·연결하지 않는다. ZIP 다운로드만으로 배포가 완료되지는 않는다.
배포 안내에는 저장소 준비, 파일 업로드, Pages 설정, Actions 권한·실행 확인, 접속 확인과 실패 시 점검 항목을 담는다. 구체적인 워크플로 문법과 권한은 구현 시점의 공식 문서로 확인한다.
6 회원과 프리미엄 확장
초기에는 로그인·회원가입 화면만 만들고 실제 백엔드 인증 요청, 계정 생성, 로그인 세션과 내 프로젝트 회원 화면은 구현하지 않는다. 입력값은 서버·브라우저 영구 저장소에 보관하지 않고 제출 시 미연결 안내를 표시한다. 모든 기본 제작 기능은 로그인 없이 이용한다.
향후 로그인한 무료 회원에게 더 많은 샘플과 테마를 제공한다. 프리미엄 구독에는 더 고도화된 편집·출력·관리 기능을 제공하는 방향으로 확장한다. 온라인 저장·버전 복원·React 출력·자동 배포는 고급 기능 후보로 둔다. 가격과 최종 등급별 기능은 사용자 검증 뒤 결정한다. 미구현 기능은 ‘준비 중’으로 표시한다. 데모 권한은 실제 유료 권한이나 보안 수단으로 사용하지 않는다.
실서비스에서는 인증 상태와 기능 권한을 별도로 관리한다. 프런트엔드의 표시·숨김 외에 서버가 프로젝트 소유권과 이용 권한을 검증해야 한다. 결제 도입 단계에서 구독 상태 변경, 갱신 실패, 취소·만료 처리와 웹훅 검증을 설계한다.
7 개발언어와 개발환경
초기 개발언어는 TypeScript, 화면은 React, 개발·빌드는 Vite를 기준으로 한다. 편집 엔진은 GrapesJS를 우선 검증한다. 코드 편집기는 VS Code, 버전 관리는 Git·GitHub, 실행 환경은 호환되는 Node.js LTS를 사용한다. 정확한 버전은 착수 시 공식 호환 정보를 확인하고 고정한다.
ZIP 생성 라이브러리는 프로젝트 저장과 사이트 패키징에 필요한 범위에서 선정한다. GrapesJS의 저장·내보내기 API는 별도 연동 계층에서 다루어 화면 코드와 분리한다. 초기 서비스는 정적 프런트엔드로 배포하며, 온라인 저장·인증 도입 단계에 Java·Spring Boot·MySQL을 추가한다.
편집 엔진의 라이선스, 공식 문서, 반응형 편집, 프로젝트 복원, 이미지 패키징과 출력 품질을 검증한 후 채택한다. 상용 SDK 기능이 오픈소스 기본 기능에 포함된 것으로 가정하지 않는다.
8 프로젝트 구조
프런트엔드 구조 기준
src/app: 라우팅과 공통 상태 연결
src/pages: 홈·제작·저장·회원 데모 화면
src/features/editor: 캔버스와 편집 엔진 연동
src/features/blocks: 블록 정의와 허용 속성
src/features/project: 프로젝트 저장·불러오기·형식 검증
src/features/export: HTML·CSS·JS 생성과 ZIP 구성
src/features/deployment: 배포 방식별 파일·안내 생성
src/features/membership: 로그인·회원가입 UI와 후속 권한 연결 지점
src/shared: 공통 UI·타입·유틸리티
public/samples: 샘플 프로젝트와 자산
데이터와 기능의 책임
편집 데이터가 기준 상태이며 캔버스와 출력 생성이 이를 사용한다. 블록 정의는 초기 내용과 수정 가능한 범위를 관리한다. 저장 기능은 재편집을, 내보내기는 독립 실행을, 배포 패키징은 호스팅별 설정을 담당한다. 상세 데이터 규격과 API는 기술 검증 뒤 확정한다.
후속 서버 구조
backend는 회원, 프로젝트, 파일, 구독 도메인으로 나눈다. Controller는 요청·응답, Service는 업무 처리, Repository는 저장소 접근, DTO는 전송 데이터, Entity는 영속 상태를 담당한다. 루트에 frontend와 backend 폴더를 분리한다. backend는 향후 Spring Boot용 공간으로 확보하되 초기에는 실행 가능한 서버, 인증 API와 DB를 구현하지 않는다.
9 개발 Phase와 완료 기준
Phase 1 기술 검증과 기본 편집
작업: GrapesJS 검증, 홈·제작·저장 이동, 기본 블록, 내용·스타일 편집, PC·모바일 미리보기, 실행 취소·다시 실행.
완료 기준: 샘플과 빈 프로젝트에서 제작 가능하며 화면 이동 시 작업이 유지되고, 모바일 미리보기에서 주요 블록이 겹치지 않는다. 엔진 채택 여부와 출력 제약을 기록한다.
Phase 2 저장과 배포 가능한 MVP
작업: HTML·CSS·JS·자산·편집 데이터 통합 ZIP 저장·복원, GitHub Pages 패키징·안내, 로그인·회원가입 UI, 오류 처리, 메이커 자체의 Actions 배포 파일과 README 준비.
완료 기준: 저장 후 복원한 결과가 일치하고, 출력 사이트가 편집 도구 없이 작동한다. 로컬 정적 환경에서 이미지·링크·모바일 메뉴를 확인하고 배포 설정 파일을 검토한다. 실제 GitHub Pages 배포 검증은 사용자가 저장소를 연결한 이후 수행하는 별도 항목으로 남긴다. 실제 인증·결제 없이 전체 UX를 완료할 수 있다.
Phase 3 실제 서비스 확장
작업: 사용자 검증 결과를 반영해 실제 인증·온라인 프로젝트 관리·서버 권한 검증을 도입한다. 이후 결제·구독을 연결하고 고급 기능을 순차 추가한다.
완료 기준: 사용자별 데이터가 분리되고 타인의 프로젝트 접근이 차단된다. 구독 상태와 기능 권한이 일치한다. React 출력과 자동 배포는 별도 검증을 통과한 기능부터 제공한다.
10 주요 리스크와 검증
출력 불일치: 대표 샘플의 미리보기와 실제 출력 화면을 비교한다.
작업 손실: 저장·복원, 페이지 이동과 잘못된 파일 가져오기 시나리오를 확인한다.
자산 누락: 모든 이미지가 ZIP에 포함되는지, 하위 경로 배포에서도 표시되는지 확인한다.
입력 안전성: 임의 스크립트를 제한하고 링크·콘텐츠를 검증한다. 업로드 파일의 형식·크기와 가져오기 파일의 구조를 제한한다.
범위 확대: 단일 페이지와 기본 블록을 먼저 완성하고, 인증·결제·React 출력은 후속 단계로 유지한다.
검증은 핵심 사용자 시나리오 중심으로 수행한다. 편집·저장·복원·내보내기 전체 흐름, 대표 화면 크기, 키보드 접근, Pages 배포를 확인한다. 이용자가 도움 없이 샘플 수정과 다운로드를 완료하는지 관찰하고 막히는 지점을 기록한다. 사업성과 유료 전환 가능성은 아직 검증되지 않았다.
11 확정 사항과 다음 작업
확정 사항: 모듈형 반응형 단일 페이지 제작, 홈 → 제작 → 저장 흐름, HTML·CSS·JS 우선 출력, 프로젝트 재편집 지원, GitHub Pages 배포 파일 지원, 로그인 없는 기본 이용, 회원·구독의 단계적 확장.
다음 작업: 편집 엔진 검증 → 기본 블록·샘플 확정 → 화면 초안 → 저장 규격과 출력 규칙 → Phase 1 구현. 프로젝트 이름은 이지웹메이커로 확정한다. 구체적인 버전, 업로드 제한, 무료·유료 한도와 가격은 아직 미정이다.

13 첫 MVP 목표와 코덱스 작업 기준
목표
빈 폴더에서 이지웹메이커를 새 프로젝트로 구축한다. 사용자는 로그인 없이 학교·공공기관 스타일 샘플이나 빈 페이지를 선택하여 블록을 편집하고, HTML·CSS·JS가 포함된 ZIP을 저장한 뒤 다시 불러와 재편집할 수 있어야 한다. 이번 문서 수정은 요구사항 확정 작업이며 구현 시작을 의미하지 않는다.
화면과 디자인
메이커 UI는 노션을 참고하여 여백, 낮은 장식 밀도, 명확한 글자 계층과 간결한 패널을 사용한다. 노션의 브랜드나 화면을 그대로 복제하지 않는다. 기본 글꼴은 한글 가독성을 우선하며 Noto Sans KR 등을 후보로 선정하고 라이선스·배포 방식을 착수 시 확인한다. 메이커 UI의 노션 스타일과 출력 샘플의 학교·공공기관 스타일을 구분한다.
학교 샘플은 기관명·메뉴·대표 이미지·학교 소개·공지 카드·연락처·푸터로, 공공기관 샘플은 기관명·대표 안내·주요 서비스 카드·공지·기관 정보·푸터로 구성한다. 단일 페이지와 기존 기본 블록을 사용하며 검색·게시판·민원 접수 등 서버 기능을 실제 작동하는 기능처럼 표현하지 않는다.
프로젝트 폴더와 환경
루트에는 frontend/, backend/, .github/workflows/와 README.md를 둔다. 프런트엔드의 기존 src 구조와 public/samples는 frontend/ 아래에 배치한다. React·TypeScript·Vite로 구현하고 backend/는 후속 Java·Spring Boot 확장용으로 확보한다. 빈 폴더 유지를 위해 최소 안내 파일을 둘 수 있으나 서버 스캐폴딩과 불필요한 의존성은 추가하지 않는다.
저장과 불러오기 수용 기준
한 번의 저장으로 index.html, styles.css, script.js, assets/와 project.json을 하나의 ZIP으로 다운로드한다. 메이커가 생성한 ZIP을 다시 불러왔을 때 블록 순서·내용·스타일·이미지가 유지되어야 한다. JSON 단독 저장을 사용자에게 추가로 요구하지 않는다. HTML·CSS·JS만 있는 외부 사이트의 완전한 편집 구조 복원은 별도 범위이며, 메타데이터가 없는 패키지는 명확하게 안내한다. 가져온 JavaScript를 편집기에서 임의 실행하지 않는다.
편집 기기 수용 기준
PC·태블릿·모바일 브라우저에서 블록 추가, 선택, 내용·스타일 수정, 순서 변경, 저장·불러오기가 가능해야 한다. 터치 드래그가 불안정한 환경을 위해 클릭 삽입과 이동 버튼을 제공한다. 기기별 패널과 버튼이 화면 밖으로 잘리지 않아야 한다. 출력 사이트의 반응형 동작은 편집기 반응형과 별도로 검증한다.
회원과 구독 범위
로그인·회원가입 화면의 레이아웃, 입력 UI와 기본 입력 검증만 준비한다. 실제 계정 생성·로그인 성공 처리·백엔드 연결·결제·권한 부여는 하지 않는다. 이후 무료 회원에게 추가 샘플·테마를, 구독 회원에게 고급 기능을 제공하도록 인증과 기능 권한의 연결 지점을 분리한다.
배포와 README 범위
메이커 데모의 배포 대상은 GitHub Pages를 기준으로 하고 GitHub Actions 워크플로를 준비한다. 워크플로는 frontend/ 의존성 설치·검증·빌드와 산출물 배포를 고려한다. 저장소 하위 경로와 라우팅 새로고침 대응을 문서화한다. 메이커 배포 워크플로와 사용자가 출력한 정적 사이트의 배포 워크플로는 구분한다.
저장소 생성·연결, push, 실제 Actions 실행과 공개 배포는 수행하지 않는다. 필요한 워크플로·설정·README 파일만 후속 구현 산출물에 포함한다. README에는 목적, 폴더 구조, 설치·실행·빌드 명령, 저장·불러오기, 배포 준비·설정, 미연결 인증, 미구현 기능, 검증 결과와 남은 배포 검증을 명시한다.
첫 MVP 완료 조건
홈 → 제작 → 저장 흐름과 작업 유지가 작동한다. 모든 기본 블록을 제공한다. 학교·공공기관 기본 샘플을 수정할 수 있다. PC·태블릿·모바일에서 주요 편집 작업을 완료할 수 있다. 통합 ZIP 저장과 재불러오기가 성공한다. 출력 사이트가 독립 실행된다. 로그인·회원가입은 UI만 제공한다. frontend와 backend가 분리되어 있다. GitHub Actions 파일과 README가 준비되어 있으며 실제 저장소 연결·배포는 수행되지 않는다.
